## Executive Summary

Path C (In-Memory Atomic Reservation with Asynchronous Persistence) completely shatters the database pessimistic locking bottleneck.

- **Path A and Path B** both suffer from the inescapable reality of RDBMS row-level locking. Whether queueing in Nginx (Path A) or inside the Node.js event loop (Path B), 100 users trying to update 1 row will serialize.
- **Path C** intercepts the request at the caching layer. By evaluating stock via a single-threaded, atomic Lua script in Redis, we achieve **sub-millisecond latency** and can process tens of thousands of requests per second. The relational database is decoupled from the user-facing request and safely updated in the background queue, completely eliminating race conditions and lock contention.
